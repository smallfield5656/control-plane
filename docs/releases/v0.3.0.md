Make Bootstrap progression depend on explicit human approval instead of placeholder inference.

Highlights:

- Add `.control-plane/bootstrap-state.json` as the versioned Current State for Bootstrap items, inputs, dependencies, and approvals
- Keep completed content pending until a human explicitly approves it through an AI Agent
- Bind approvals to normalized SHA-256 revisions and mark changed or downstream items as `Needs Review`
- Add a vendor-neutral Project Bootstrap Skill adapter that records an approval only after an explicit human instruction
- Validate schema versions, dependency order, cycles, repository-relative paths, symlinks, UTF-8 inputs, and approval scope conservatively
- Keep `control-plane next` and `control-plane doctor` read-only and offline

Migration:

Projects created before v0.3.0 do not receive Template updates automatically. Copy these assets from the v0.3.0 Template before using the new CLI:

- `.control-plane/bootstrap-state.json`
- `.agents/skills/project-bootstrap/scripts/record-approval.mjs`
- the approval workflow updates in `.agents/skills/project-bootstrap/SKILL.md` and `agent/workflows/bootstrap.md`

After reviewing the current Product, Delivery, and Architecture inputs, explicitly approve each applicable item through the AI Agent. The Agent runs:

```bash
node .agents/skills/project-bootstrap/scripts/record-approval.mjs <item-id>
```

Standard item IDs are `product-goal`, `requirements`, `constraints`, `delivery`, and `architecture`. Missing state does not fall back to legacy completion inference; `doctor` reports migration as required.
